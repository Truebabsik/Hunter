# Экраны исхода: победа, побег, падение, воскрешение, конец забега

Спека. Утверждена в обсуждении; код по ней ещё не писался.

## 1. Задача

После боя игрок должен увидеть исход, **понять, что потерял или получил**, и узнать,
что срок богини идёт. Сейчас всё это делает один экран `result_screen.gd` с двумя
состояниями («ПОБЕДА» / «ПОРАЖЕНИЕ»), и он врёт дважды:

- **побег показан как поражение**, хотя ты ушёл живым и с частью добычи;
- **падение показано как смерть**, хотя богиня возвращает — а после срока
  возвращать перестаёт, и это разные события.

## 2. Четыре исхода и пять экранов

Исходов **четыре**, экранов **пять**: падение — это два такта (боль, потом дар).

| Исход | Условие | Экраны |
|---|---|---|
| **Победа** | зверь повержен | VICTORY |
| **Побег** | ушёл, бросил часть ноши | ESCAPE |
| **Падение** | проиграл, **срок идёт** | DEFEAT → RESURRECTION |
| **Конец забега** | проиграл, **срок вышел** | RUN_OVER |

**Меньше нельзя.** Побег нельзя показывать как поражение; смерть после срока
нельзя показывать как падение — во втором случае за тобой не приходят.

## 3. Решающая функция — в ядре

```gdscript
# core/ui_data/outcome.gd — НОВЫЙ файл, чистый (без Node и UI)
class_name Outcome

const VICTORY := &"victory"
const ESCAPE := &"escape"
const DEFEAT := &"defeat"
const RESURRECTION := &"resurrection"
const RUN_OVER := &"run_over"

## Какой экран показать. Чистая функция: только по состоянию, без побочных эффектов.
static func resolve(result: HuntResult, grace_active: bool, rank_dropped: bool) -> StringName
```

**Почему в ядре.** Правило проекта: логика, которую можно проверить прогоном,
живёт в `core/`. Выбор экрана — именно такая логика. Если её оставить в разметке,
её сломает правка вёрстки, и никто не заметит.

`rank_dropped` нужен, чтобы отличить первое падение (ранг не откатился, откатывать
некуда) от настоящего понижения: текст экрана разный.

## 4. Правило двух цен — в одном месте

```gdscript
# hunt_result.gd, в _apply_defeat
run_over = not GameState.grace_active()
```

Срок вышел — смерть окончательна. Срок идёт — падение с воскрешением.
**Логика не дублируется нигде больше**, поэтому её нельзя рассинхронизировать.

## 5. Данные для экранов

`HuntResult` уже считает почти всё; добавляются поля:

| Поле | Смысл | Статус |
|---|---|---|
| `coins_lost` | сколько монет сгорело при падении | **новое** |
| `bag_lost` | стоимость брошенной/потерянной ноши | есть |
| `run_over` | смерть была окончательной | **новое** |

`outcome` **не хранится в `HuntResult`**: его вычисляет `game_root` через
`Outcome.resolve(...)` и передаёт экрану отдельно. Так решающая функция остаётся
чистой, а `HuntResult` — только числами.

Строку про срок на экране воскрешения собирает **сам экран** из
`GameState.days_left()` и `GameState.grace_active()`. Хранить её в результате
не нужно: это представление, а не итог охоты.

## 6. Содержание экранов

### 6.1 ПОБЕДА

```
ПОБЕДА
Хруз, береговой трущобник — повержен

Слава: 22 → 24   +2 (победа)
Добыча: Панцирная пластина, Ракушечный порошок → в ношу

┌ ДОСЬЕ ПОПОЛНЕНО ───────────────────┐
│ Он задумывал: «прыжок-навал»        │
│ Запомнил: «припадает к земле»       │
│ Уязвимость: «лёд, дальний»          │
└─────────────────────────────────────┘
Слава: 24 / 35 (до следующего 11)

[ ПРОДОЛЖИТЬ ]
```

**Строка «Он задумывал: …» обязательна.** Она закрывает критерий GDD 13.2
(«игрок понимает, почему угадал»). Данные для неё уже есть: `last_scenario_label`
и `dossier_gained`.

### 6.2 ПОБЕГ

```
ТЫ УШЁЛ
Громун, гривастая гарпуна — остался позади

Брошено: 12 монет добычи
В ноше осталось: на 36 монет
Слава не пострадала: отступление не позор

[ ПРОДОЛЖИТЬ ]
```

Тон **не осуждающий**: по GDD побег стоит материи, а не репутации.

### 6.3 ПОРАЖЕНИЕ (падение, срок идёт)

```
ТЫ ПАЛ
Скорб, костяная башня

Монеты сгорели: 87
Ноша осталась там: 45
Слава: 24 → 15   −9
РАНГ ПОНИЖЕН: Ветеран
Клеймо на знаке ранга.

«Ты выжил. Гильдия помнит. Возвращайся.»

[ ДАЛЬШЕ ]
```

**Цена падения (решено): монеты, ноша, слава И ранг.** Смерть перестала быть
концом забега, поэтому именно откат ранга — её настоящая цена. Клеймо остаётся
и исчезает через превосхождение.

Строки «РАНГ ПОНИЖЕН» нет, если откатывать было некуда — тогда вместо неё
«Ранг сохранён: <ранг>».

### 6.4 ВОСКРЕШЕНИЕ

```
ТЕБЯ ВЕРНУЛИ
Богиня не объясняет. Она просто не дала умереть.

Осталось дней: 17
Дни потрачены: этот поход стоил 3

Не сгорело:
  • Досье: 34 факта
  • Навыков: 5

[ ВЕРНУТЬСЯ В ГОРОД ]
```

**Остаток дней показывается всегда.** Это тот кадр, где срок становится
осязаемым: игрок видит не «45 в начале забега», а «17 прямо сейчас».

**Вариант, если срок истёк прямо в этом походе** — последняя строка меняется
и её нельзя пропустить:

```
СРОК ВЫШЕЛ. Дольше она ждать не будет.
```

### 6.5 КОНЕЦ ЗАБЕГА

```
ЗАБЕГ ОКОНЧЕН
Богиня больше не отвечает.

Ранг: Ветеран        Слава: 41
Прожито дней: 46 из 45        Охот: 14
Побед 9 · Побегов 4 · Падений 1
Достижений: 12 из 22

──────────────── ХРОНИКА (38 записей) ────────────────
День 46  ▸ смерть      Ламент, коронованный пожиратель
День 43  ▸ победа      Ламент — слава +12, ранг Мастер
День 40  ▸ откат       РАНГ ПОНИЖЕН: Ветеран
…
День 3   ▸ победа      Хруз — слава +1
…и ещё 12 записей раньше

[ НОВЫЙ ЗАБЕГ ]
```

**«Прожито 46 из 45»** — единственное место, где видно, что черта перейдена.
Число больше срока читается как приговор без лишних слов.

**Хроника — в обратном порядке, последние 40 записей**, с обязательной подписью,
если записей больше. Молчаливый обрез запрещён: игрок решит, что хроника
оборвалась. Тон: сводка говорит *что ты успел*, хроника — *как ты жил*,
поэтому она идёт **после** сводки.

**Кнопка НОВЫЙ ЗАБЕГ** делает `GameState.reset()` и открывает город.

## 7. Переходы

Держит `game_root.gd` — единственный узел, который знает об экранах:

```
бой ──battle_finished──> Outcome.resolve(...)
   ├─ VICTORY       → результат ──[ПРОДОЛЖИТЬ]──> город
   ├─ ESCAPE        → результат ──[ПРОДОЛЖИТЬ]──> город
   ├─ DEFEAT        → поражение ──[ДАЛЬШЕ]──> воскрешение ──[В ГОРОД]──> город
   └─ RUN_OVER      → конец забега ──[НОВЫЙ ЗАБЕГ]──> reset → город
```

**После падения игрок не возвращается в бой**, а идёт в город обобранным.
Контракт остаётся незакрытым — это работает вместе с правилом «новый заказ
нельзя, пока этот не сдан».

## 8. Экран один, состояний пять

`result_screen.gd` получает `outcome` и собирает заголовок, тело и кнопку по нему.
**Пять отдельных сцен не делаем**: их пришлось бы держать синхронными вручную,
а рассинхронизация знаний у нас уже была (два описания модификаторов: GDD 11.6
и 12.3).

Тело — `RichTextLabel` внутри `ScrollContainer` с фокусом на первой строке.
Прокрутка обязательна для хроники и желательна для поражения.

## 9. Проверка

### 9.1 Режим `--outcomes` (новый)

Прогоняет таблицу и пишет результат в `_outcomes_out.txt`.

| `grace_active` | `victory` | `fled` | `rank_dropped` | Ожидаемый экран |
|---|---|---|---|---|
| да | да | — | — | VICTORY |
| да | — | да | — | ESCAPE |
| да | — | — | да | DEFEAT |
| да | — | — | нет | DEFEAT |
| **нет** | — | — | — | **RUN_OVER** |

### 9.2 Контроль суммы в отчёте цикла

В `--loop` добавляются счётчики исходов и проверка:

```
побед + побегов + падений + концов забега = числу боёв
```

Это та же защита, что поймала симулятор, считавший побег поражением
(«100 поражений» при 71 побеге). Каждый бой обязан дать **ровно один** исход.

### 9.3 Что прогоном не проверяется

**Вёрстка**: помещается ли хроника, читается ли тон, не обрезана ли кнопка.
Это смотрим глазами — режимом `-- --shots`, который сохраняет кадр в PNG.

## 10. Открытые вопросы (не блокируют)

- **Хроника живёт только в памяти забега.** Если перезапуски будут частыми,
  понадобится её сохранение между забегами. В текущий дизайн не входит: забег
  один, с благодатным периодом.
- **Побег сейчас падает в ветку поражения** и в счётчиках, и в тексте. Спека это
  чинит для экранов; проверить, не осталось ли других мест, где побег считается
  поражением (главный подозреваемый — достижения).
